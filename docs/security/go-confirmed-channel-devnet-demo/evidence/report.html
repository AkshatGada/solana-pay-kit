Funding transaction in Solana Explorer · Funded channel in Explorer

Both binaries use the same harness and fixture, with fresh in-memory stores for each case. The baseline binary overlays only the three production files with their originals from the base commit. A transparent loopback proxy forwards real requests to api.devnet.solana.com and records unchanged requests and responses. The run modes submit no transactions.

The missing-channel credential uses the earlier successful mint/setup signature, independently confirmed by RPC; its derived channel account is absent. The overclaim and valid control use the genuine channel-open signature. The optional recentSlot echo is omitted for these already-broadcast signature-only opens; the patch recovers the channel’s actual open slot.

A real compatibility failure was found and corrected

The initial patch used the generated Go enum’s value 0 for the channel discriminator. Both the IDL’s explicit accountDiscriminator.channel value and the real account use 1. That caused the valid control to fail in patched-run2. The local patch now checks 1 explicitly, and its tests use 1 plus negative cases for 0 and 2. The generated package was left untouched. The original two patch files are preserved under pre-demo-patch/.

Run history retained

  • run1: both versions rejected the old recentSlot echo before channel verification. This was a harness correction, not a security result.
  • baseline-run2: all three accepted; patched-run2: funded control incorrectly rejected because of the discriminator mistake.
  • baseline-run2 + baseline-run3, patched-run3 + patched-run4: repeatable final behavior with fresh stores.

Validation and limits

Full Go short tests passed; go vet -composites=false ./... passed. Builds used cached modules, GOMAXPROCS=2 and GOFLAGS=-p=2. Hosted sandbox E2E was excluded by -short. This HTTP/ledger demo covers signature-only push opens on the canonical Devnet program; attached-transaction and other rejection paths are covered by the Go regression suite, not demonstrated here as real-chain scenarios. No settlement, fund withdrawal or real merchant pricing flow was exercised. The resource handler is a minimal local demonstration.
