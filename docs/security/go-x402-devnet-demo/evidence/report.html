What the evidence shows

The fully signed representation was deliberately prepared with the disposable operator key. This tests replay handling when both valid representations are available; it does not establish that an untrusted client can obtain the operator-signed form before the first submission or confirmation.

Two representations of the same payment become identical signed wire bytes. The baseline lets simultaneous requests reserve different replay keys. Both submissions can be accepted before confirmation, and both HTTP handlers run. The ledger still executes the transfer once.

The patch reserves the actual transaction signature before broadcast, so the second request receives HTTP 402 with signature_consumed

Sequential baseline replay was already rejected by Devnet preflight as AlreadyProcessed. This demonstration establishes the concurrent case; it does not claim sequential replay always succeeds.
